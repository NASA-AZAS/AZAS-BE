# LLSN regression fixtures

These are test-only extracts of the user-supplied `LLSN-Java21` bundle.
They do not establish an independent scientific benchmark and are not used as a runtime cache.

- `llsn-golden.json`: both scenarios (578 epochs) from `results/analysis/analysis_result.json`, retaining upstream angles, horizons, clearances, states and metrics. The original result SHA-256 is embedded in the file.
- `sun-observer.json` and `earth-observer.json`: original observer responses for 2026-12-01 through 2026-12-03, 10-minute cadence. `fixture-provenance.json` retains original filenames, queries and hashes.
- Terrain samples come from the already versioned landing-screen resource bundle; no duplicate DEM or terrain seed is included here.

For the visibility fixtures above, file/CLI orchestration and Horizons cache handling were replaced by the backend entry adapter and HTTP client. UTC daily aggregation is an integration addition and is checked against upstream per-epoch states.

`launch-options-golden.json` contains the formatted output of LLSN ver2 `launch-options results/launch-flow-example/date_opportunities.json Site01`. The original output SHA-256 is `32a84857fea5d6e47fd57ba731d13a8712e9fccb4883dcc51af689937749a381`. The API test uses these 13 test-only sites and compares every candidate and its UTC timestamps.

`earth-vector.json` and `moon-vector.json` are the two original Horizons responses recorded in LLSN ver2 `results/launch-flow-example/trajectory.json` for 2027-01-18 22:10 UTC. `kennedy-trajectory-samples.json` contains its 701 transfer samples in order. To reproduce, run `java -jar llsn.jar launch-trajectory results/launch-flow-example/launch-options.json Kennedy-1799883120 trajectory.json --offline` in the reference module. The API test serves these responses over loopback and checks UTC and elapsed seconds exactly, positions within 1e-6 km and velocities within 1e-9 km/s.


`transfer-options-golden.json` was generated by invoking the original package-private `llsn.Orbit` in the supplied ver2 JAR, not the backend implementation. The probe evaluates `[7000,500,-100]` to `[310000,180000,-45000]` km over 259200 seconds with mu=398601, tolerance=0.01 for SHORT_WAY and LONG_WAY, plus a -3600 second propagation of `[7000,0,0]`, `[0,7.54605329,0]` with mu=398600.4418. Tests compare velocities within 1e-8 km/s, position residuals within 1e-6 km, and backward position/velocity within 1e-6 km / 1e-9 km/s.

- Original `src/Orbit.java` SHA-256: `eaebc215dcecf10a576b7534d10a20a80778e7c1ab14199cdf05cd6a16a7229e`.
- Reproduce using a class in package `llsn` on that JAR's classpath, calling `Orbit.lambert(position,target,seconds,mu,branch,tolerance)` and `Orbit.propagate(new Orbit.State(position,velocity),seconds,mu)`, then `Json.encode` of the returned values.
